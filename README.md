# YU-GI-OH DESIGN LAB

유희왕 커스텀 테마의 **원문·CDB·Lua를 검수하는 무료 브라우저 연구소**입니다.

## V0.4 — 스마트 파일 관리

- **한 개씩 추가:** 자료실의 원문 ZIP, 교차 검수의 패키지 ZIP/CDB/Lua, 상단의 \`＋ 추가\` 버튼 중 어느 곳에서 가져와도 동일한 파일 보관함에 누적합니다.
- **새로고침 후 자동 복원:** IndexedDB를 사용할 수 있으면 브라우저 내부에 원본 파일 바이트를 저장하여 다음 방문에 자료실과 교차 검수를 자동으로 복원합니다. 사용자 파일은 서버나 GitHub로 전송하지 않습니다.
- **파일 보관함:** 상단의 \`저장 자료 n개\`를 눌러 등록 파일명·용량·해시를 확인하고 개별 삭제·전체 삭제할 수 있습니다.
- **중복/버전 충돌:** SHA-256이 같은 파일은 추가하지 않으며, 같은 이름의 다른 내용은 모두 남긴 채 충돌 안내를 표시합니다. 구버전/최신 버전 판단은 사용자 몫입니다.
- **제한:** 파일당 32MB, 총 96MB, 최대 120개. 원문 자료실·검수 엔진에는 각각 별도 ZIP/텍스트 분석 크기 제한이 존재합니다.
- **임시 모드:** IndexedDB를 사용할 수 없는 브라우저에서는 임시 세션으로 작동하고, 지속 저장이 되지 않는다는 경고를 표시합니다.
- **YDK:** 현재 보관만 지원합니다. 덱 초동·전개 분석 기능은 이후 버전에서 개발합니다.
- **중요:** 브라우저 데이터 삭제·시크릿 모드·저장 공간 정리 정책으로 자료가 사라질 수 있습니다. **원본 ZIP과 Lua/CDB를 PC에도 반드시 보관**하세요.
- V0.3.1에서 읽던 파일은 메모리에만 있으므로, V0.4 최초 이용 시 **원문 ZIP을 한 번 더 등록**해야 합니다.

### 사용 흐름
1. 페이지에서 종언성서 원문 ZIP을 **한 번 등록**합니다.
2. \`교차 검수\`로 이동해 파계잔영 CDB/Lua 패키지 ZIP을 **별도로 등록**합니다. 두 파일을 동시에 선택할 필요가 없습니다.
3. 자료실에서 86종을 열람하고, 교차 검수에서 최신 로컬 보관 파일 집합을 비교합니다.
4. 새로고침해도 등록 목록이 다시 표시되는지 확인합니다.

## V0.3.1 — 카드 원문 집중 읽기

- 자료실에서 카드를 선택하고 **「⤢ 이 카드 원문 크게 보기」**를 누르면 화면 전체를 읽기 공간으로 사용할 수 있습니다.
- 처음에는 **18px 글씨**로 원문 효과를 모두 펼쳐서 표시합니다. **가− / 가＋**로 글씨 크기를 조정할 수 있습니다.
- 왼쪽에서 카드 검색·선택, 상단에서 이전·다음 카드 이동, **ESC**로 닫기를 지원합니다.
- 원문 카드가 로딩된 뒤에는 필요 없는 업로드 안내·통계 영역을 숨겨 기본 카드 패널도 더 넓게 사용합니다.
- 집중 읽기는 카드 효과를 보기 좋게 재배치할 뿐 원본 TXT를 수정하지 않으며, 분석·검증 결과로 간주하지 않습니다.

## V0.3 — 작업실형 화면 개선

- 상단 또는 왼쪽 메뉴에서 **카드 자료실 / 교차 검수 / 덱 연구소(준비 중)**를 전환합니다.
- PC에서는 긴 페이지를 스크롤하는 대신 **카드 목록과 효과 상세 패널만 각각 스크롤**합니다.
- 카드 효과는 ①·②·③을 따로 접거나 펼치며, \`모두 펼치기\` 기능을 제공합니다.
- 원문 메모는 자료실 하단의 접이식 서랍에서 확인합니다.
- 레이아웃만 바뀌었으며 기존 ZIP·TXT 불러오기, 카드 검색, CDB·Lua 정적 검사 기능은 유지됩니다.
- 탭 선택은 주소의 \`#library\`, \`#audit\`, \`#deck\`에 반영됩니다. 새로고침하면 탭이 유지되며, V0.4부터는 **IndexedDB에 등록된 파일도 자동 복원**됩니다. 저장을 사용할 수 없는 브라우저에서는 임시 모드로 표시합니다.
- 덱 연구소는 현재 안내 화면이며 실제 분석 기능은 미구현입니다.

## V0.2 — 원문·CDB·Lua 교차 검수
- **파일 하나씩 누적 가능(V0.4)**: 원문 TXT/ZIP부터 등록한 후 각 테마의 시험패키지 ZIP 또는 개별 CDB/Lua를 따로 추가할 수 있습니다.
- CDB: SQLite의 \`datas\`/\`texts\` 테이블에서 ID·이름·설명·선택지 문자열 읽기
- Lua: 카드 ID의 \`c<ID>.lua\` 대응, \`initial_effect\` 존재, 공용 \`*_common.lua\` 참조 검사
- 효과 문구: 원문과 CDB의 번호 붙은 효과 항목을 대조하고 차이와 순서 확인
- 파일 버전 충돌, 카드 ID/이름 누락, 선택지 설명 문자열 누락 가능성 경고
- 실제 EDOPro 구동 없이 **정적 진단 보고서** Markdown 파일로 저장
- CDB만 업로드한 경우에도 **CDB↔Lua 검사는 가능**, 설계 원문 대조는 미검증으로 표시

### 실제 사용
1. 상단의 **교차 검수** 탭을 엽니다.
2. **원문 ZIP**을 먼저 등록하고, 그다음 **파계잔영 시험패키지 ZIP**을 따로 등록해도 됩니다.
3. 오류 후보/검토 필요 탭을 선택해 카드별 근거를 확인합니다.
4. \`종언성서_원문_CDB_Lua_정적검수_V0.2.md\` 보고서를 내려받습니다.

> **검사 수준 경계**: 문구 비교는 유사한 뜻의 다른 표현도 차이로 표시할 수 있습니다. Lua 검사는 파일과 일부 정적 패턴만 확인하므로, Lua 구문 전체·EDOPro API·효과의 적법한 처리·실전 성능까지 판정하지 않습니다. '오류 후보'가 반드시 실제 버그를 뜻하지는 않습니다.

## 파일과 개인정보
- 업로드한 파일을 서버로 보내지 않습니다. 브라우저 내에서만 분석하며, 사용자가 등록한 파일은 가능한 경우 IndexedDB에 로컬 저장됩니다. 저장이 불가능하면 임시 모드로 동작합니다.
- 첫 실행 시 JSZip과 sql.js 코드·WASM은 공개 CDN을 통해 로드됩니다. **실제 카드 ZIP·CDB·Lua 데이터는 CDN으로 업로드하지 않습니다.**
- GitHub 저장소에는 업로드한 원본 CDB·Lua·개인 파일을 자동 커밋하지 않습니다. 등록 자료는 사이트별 브라우저 IndexedDB에 저장되며, 다른 기기·브라우저에는 자동 동기화되지 않습니다.
- 공개 페이지를 사용하더라도 업로드 내용이 공개 저장소에 게시되지는 않습니다.
