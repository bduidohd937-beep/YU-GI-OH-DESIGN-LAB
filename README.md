# YU-GI-OH DESIGN LAB

유희왕 커스텀 테마의 **원문·CDB·Lua를 검수하는 무료 브라우저 연구소**입니다.

## V0.8 — 덱 연구소 최초 공개: YDK 구성·초동 확률

기존 `준비 중`이었던 덱 연구소를 실제로 작동하는 **브라우저 전용 덱 분석 작업실**로 변경했습니다.

- **YDK·ZIP 불러오기:** 화면에서 `.ydk`를 업로드하거나 ZIP 안에 포함된 `.ydk`를 검색해 읽습니다. 기존 저장 자료는 새로고침 후 자동으로 재사용하며 파일 저장 기능은 V0.4 IndexedDB 보관함을 공유합니다.
- **3개 존별 덱 분석:** 메인·엑스트라·사이드 각각의 카드 ID와 장수, 동일 카드 매수를 그대로 유지하며 표로 표시합니다. 40장으로 임의 압축하지 않고 **40~60장** 중 실제 구성된 장수를 기준으로 확률을 계산합니다.
- **CDB 카드명/타입 연동:** 교차 검수에서 불러온 CDB ID와 연결해 카드명, 몬스터·마법·함정 분포를 표시합니다. 알 수 없는 카드명은 마음대로 추측하지 않고 **미확인 카드 [ID]**로 남깁니다.
- **구조 경고:** 메인 덱의 일반적인 40~60장 범위, 엑스트라·사이드 각각 15장 기준, 같은 카드 ID 3장 초과, 메인·엑스트라 타입 혼재 등을 정적으로 안내합니다. 금지/제한 목록 및 OCG 최신 규정은 검증하지 않습니다.
- **사용자 지정 초동/연장 카드:** 메인 덱 카드마다 **초동**과 **연장** 체크박스를 제공합니다. 선택 정보는 덱 내용별로 로컬 저장되며 원래 카드 데이터는 수정하지 않습니다.
- **패 확률 연구:** 현재 메인 덱 장수 기준 선공 5장/6장 가정에서
  - 초동 카드 **1장 이상** 확보
  - 초동 카드 **2장 이상** 확보
  - 지정한 **초동과 연장 카드를 각각 1장 이상** 확보
  확률을 하이퍼지오메트릭 조합으로 정확 계산합니다. 동일 카드를 초동·연장 양쪽으로 지정하면 해당 카드는 두 범주에 포함되는 것으로 계산하며 중복 지정 수를 표시합니다.
- **보고서:** `덱연구소_덱이름_분석_V0.8.md`에 존별 구성, CDB 미확인 ID, 사용자가 지정한 초동 확률, 구조 경고 및 검사 한계를 저장합니다.

### 이용 방법

1. [덱 연구소](https://bduidohd937-beep.github.io/YU-GI-OH-DESIGN-LAB/#deck)로 이동합니다.
2. **＋ YDK 덱 추가**로 EDOPro 덱 파일을 불러옵니다. 이미 보관함에 있는 YDK면 자동으로 표시됩니다.
3. 해당 테마의 CDB도 등록했다면 카드 ID 대신 이름과 종류가 보입니다.
4. 오른쪽에서 초동·연장 카드를 직접 체크하고 **선공 5장 / 6장 가정** 확률을 비교합니다.
5. **덱 분석 보고서 ↓**로 결과를 저장합니다.

**중요:** 통계는 카드가 처음 패에 들어올 확률이지 카드 효과 발동 가능성·전개 성공률·견제 성능·승률이 아닙니다. 실제 덱 운영의 효과적 루트나 OCG 금제에 대한 검증을 수행하지 않습니다. **필요한 다음 단계는 카드 효과에 근거한 원핸드/투핸드 분류와 실전 샘플링**입니다.

## V0.7.4 — 실전 실패 원인 조사·수정 검토·재시험 관리

V0.7.3에서 수동 저장한 EDOPro 시험 결과 중 **실패 / 재검증 필요 / 보류**를 조사 대기열로 자동 분류합니다. 기존 정적 카드 검사 결과와 사용자 로그를 연결하지만 원인 확정 및 Lua 자동 수정은 하지 않습니다.

- **실패 조사 모드:** 교차 검수에서 테마를 선택한 뒤 `실전 기록 열기 → 실패·재검증 조사 목록 보기`로 해당 시험만 표시합니다. 아직 사용자가 기록한 시험이 없으면 조사를 만들어 낼 수 없습니다.
- **코드 근거 연결:** 로그에 포함된 `c990470109.lua:42` 형식의 파일명·줄번호를 읽어 카드 ID를 찾아봅니다. 연결된 Lua에서 해당 줄 앞뒤 코드를 최대 5줄로 표시합니다.
- **버전 보호:** 로그 기록 당시의 설치 버전과 현재 검수된 Lua 파일의 버전이 다르거나 버전을 알 수 없으면 해당 줄의 코드가 같은 버전의 근거라고 표시하지 않습니다. 다른 카드 ID가 로그에 함께 나오면 별도 참조로 구분합니다.
- **정적 검사 후보와 대조:** 코드 줄번호 외에 기존 `OPTIONAL_TRIGGER_TIMING`, `ATTACK_API_COMPAT` 등 카드별 정적 검토 항목도 참고 후보로 표시합니다. 로그에 나온 항목이 실제 오류 원인이라는 판정은 아닙니다.
- **수동 조사 단계:** 사용자는 `원인 조사 중`, `수정안 검토`, `수정 후 재시험 대기`를 선택해 조사 가설·권장 수정 방향·재현 절차를 기록할 수 있습니다. 수정 검토 및 재시험 상태에는 필요한 내용 입력을 요구합니다.
- **기록/백업:** 이전 V0.7.3 시험 결과 이력은 유지합니다. 조사 메모는 별도 브라우저 저장소에 보관하고, `디자인랩_실전시험및조사_백업_V0.7.4.json`을 통해 시험 결과와 조사 기록을 함께 백업·복원합니다. 기존 V0.7.3 JSON도 계속 가져올 수 있습니다.
- **공유용 보고서:** `실패 조사·재시험 목록 ↓`에서 선택한 테마의 재현 단계, 사용자 증상, 코드 근거, 조사 가설, 수정안, 재시험 절차를 한글 Markdown으로 저장할 수 있습니다.
- **완료 기준:** 시험에 성공한 기록이 새로운 최신 결과로 저장되면 해당 효과는 더 이상 실패 조사 대기열에 보이지 않지만, 예전 실패 시험 결과 기록은 유지합니다.

### 사용법

1. DESIGN LAB 검수실에서 천망성역 선택 → `실전 기록 열기`.
2. EDOPro에서 실제 시험한 라지엘 등 카드의 실패/보류 결과와 버전, 증상 또는 로그를 먼저 저장합니다.
3. `실패·재검증 조사 목록 보기` 클릭 → 해당 카드의 Lua 오류 줄·정적 근거 검토.
4. **원인 조사 중 → 수정안 검토 → 수정 후 재시험 대기** 순서로 가설과 수정 방향, 재시험 절차를 기록합니다.
5. 시험 결과 및 조사 JSON을 백업하고, 재시험 후 새로운 결과를 별도 이력으로 기록합니다.

**제한:** 로그와 상태는 사용자가 직접 제공한 기록입니다. DESIGN LAB이 EDOPro를 직접 실행하거나 원인을 입증하지 않습니다. 저장된 기록을 초기화하거나 브라우저 데이터를 삭제하면 데이터가 사라질 수 있으므로 JSON 백업을 권장합니다.

## V0.7.3 — EDOPro 실전 검증 기록 시스템

정적 검사로 찾은 후보를 실제 EDOPro 수동 시험 결과와 연결하는 브라우저 기록 작업실입니다.

### 새 기능

- **실전 기록 화면:** `교차 검수 → 천망성역 → 실전 기록 열기`에서 세력별 시험 목록과 효과 원문·재현 절차·기대 결과를 함께 확인합니다. 가독성을 위해 별도 큰 창을 사용합니다.
- **번호 효과별 시험:** 기존 소환 절차, Lua 정적 문제 후보 외에 ①②③ 효과마다 별도 미실행 항목을 생성합니다. 펜듈럼 효과 ①과 몬스터 효과 ①도 각각 기록할 수 있습니다.
- **수동 판정:** 실제 EDOPro에서 시험한 뒤 `통과/실패/보류/재검증 필요` 중 하나를 직접 선택합니다. **아무것도 입력하지 않은 항목은 항상 미실행**입니다.
- **필수 정보:** 실제 EDOPro 설치본의 카드 패키지 버전과 판정이 필요하며, **실패 판정에는 실제 증상이나 Lua 오류 로그 중 하나 이상이 필수**입니다.
- **오류 로그 참조:** 텍스트 로그에 나타난 `c990470109.lua:42` 같은 카드 스크립트 ID·줄번호를 찾아 기록합니다. 코드 실행이나 원인 확정은 하지 않습니다.
- **변경 이력:** 같은 효과를 여러 버전에서 반복 테스트하면 이전 기록을 덮어쓰지 않고 시험 시각·판정·설치 버전·메모·로그를 이력으로 보존합니다.
- **버전 변경 감지:** 검사 중인 Lua 파일 버전 또는 번호 효과의 기대 결과 문구가 마지막 기록과 달라지면, 예전 `통과`를 현재 버전의 정상으로 표시하지 않고 **재검증 필요**로 표시합니다.
- **브라우저 전용 저장:** 개인 시험 기록은 `localStorage`에만 저장하며 서버 업로드나 EDOPro 자동 실행을 하지 않습니다. 브라우저 데이터 삭제, 시크릿 모드 또는 저장소 차단 시 데이터가 사라질 수 있으므로 JSON 백업을 권장합니다.
- **백업/복원:** `디자인랩_실전시험기록_백업_V0.7.3.json`으로 기록을 저장하고 복원할 수 있습니다. 복원은 기록 ID 기준으로 기존 기록에 병합하며, 내보내기는 현재 입력된 전체 이력을 포함합니다.
- **보고서:** 현재 선택 테마의 실전 시험 상태와 최신 기록을 `종언성서_천망성역_EDOPro_실전검증기록_V0.7.3.md`로 다운로드할 수 있습니다.
- **기존 빈 시험 목록과 구분:** `빈 시험 목록 ↓`은 직접 체크할 서식이며, 입력된 실제 결과는 `실전 기록 열기 → 시험 결과 보고서 ↓`에서 확인합니다.

### 《천망성역》 첫 시험 권장

1. V0.9.1 본체 + V0.9.2 패치가 EDOPro에 실제 설치됐는지 확인합니다. DESIGN LAB에 ZIP을 넣는 것만으로 설치되지는 않습니다.
2. 웹 교차 검수에서 **천망성역**을 선택한 뒤 **실전 기록 열기**를 클릭합니다.
3. 검색창에서 `세피르`, `천벌의 광선`, `라지엘`, `역사의 역전`을 순서대로 찾아 실행 절차와 기대 결과를 확인합니다.
4. 실제 EDOPro에서 시험한 효과만 판정하고 실패할 경우 증상 또는 로그를 함께 저장합니다.
5. JSON 백업 후 Markdown 보고서를 확인하여 재현된 문제와 코드 수정 후보를 구분합니다.

**검증 범위:** 실제 EDOPro 실행은 사용자가 수행하며, DESIGN LAB은 입력된 결과를 기록하고 관계된 Lua 파일 참조를 정적으로 탐색할 뿐입니다. 저장된 `통과`는 사용자가 직접 입력한 기록이지 자동 보증이 아닙니다.

## V0.7.2 — 가져오기 진단 읽기 개선 및 비원문 TXT 자동 제외

실제 《천망성역》 V0.9.1+V0.9.2 패키지를 검수할 때 생긴 경고 표시 문제를 고쳤습니다.

- **가져오기 경고를 크게 보기:** 기존 좁은 드롭다운 대신 `가져오기 안내 → 넓게 보기`를 누르면 화면 대부분을 차지하는 별도 진단창이 열립니다. 확인 필요/정상 처리 안내/제외된 문서를 분리하고, 전체 내용을 복사할 수 있습니다.
- **불필요한 파일 오류 제거:** SHA256 목록·검수 보고서·설치 안내처럼 카드 원문 구역이 없는 일반 TXT는 검사 대상에서 제외하고 목록만 보여 줍니다. 원본 파일은 로컬 보관함에 유지합니다. `원문`이라는 이름인데 필수 형식이 깨진 파일은 계속 확인 경고를 냅니다.
- **테마 원문 중복 처리:** 서로 동일한 카드 문구의 중복은 경고하지 않습니다. 서로 다른 버전의 카드 문구가 있으면 최신 명시 버전을 우선 표시하고 기준본을 안내합니다. 같은 버전인데 문구가 다르면 확인이 필요한 충돌로 표시합니다.
- **패치 Lua 중복 집계 제외:** 천망성역의 본체 카드 Lua 19개 + V0.9.2 개정 Lua 2개를 불러왔을 때 테마 버튼에는 고유 ID 기준 **19종**이 표시됩니다.
- **중요한 실패는 유지:** CDB 읽기 실패, 잘못된 카드 원문, 기준 버전 불확실성은 숨기지 않습니다.
- **테스트:** 실제 사용 사례를 재현하는 파서/버전/진단 UI 회귀 테스트를 추가했습니다.

### 새 화면 사용법

1. 기존 파일 3개를 다시 올리지 않아도 됩니다. 저장된 자료는 새로고침 시 자동 재분석합니다.
2. DESIGN LAB 웹에서 `Ctrl + Shift + R`로 새로고침하세요.
3. 교차 검수에서 **「가져오기 안내 · 넓게 보기」**를 눌러 확인 필요와 처리 안내를 살펴보세요.
4. 아래 카드 원문 화면은 기존 25:75 비율 그대로 유지됩니다.

## V0.7.1 — 실제 천망성역 패키지 검수 후 오탐 보정

《천망성역》 V0.9.1 전체 CDB·Lua ZIP과 V0.9.2 《라지엘》·《역사의 역전》 긴급 패치 ZIP을 대조하며 발견한 입력 자료 오탐을 보정했습니다.

- **선택 설치 자료 분리:** ZIP의 `공용_아벨_선택설치` 또는 `optional_install` 폴더 아래 CDB·Lua·TXT는 기본 테마 검수에서 제외합니다. 사용자에게 건너뛴 파일 수를 안내하며, **원하는 경우 개별 CDB·Lua 파일을 직접 업로드하면 검수할 수 있습니다.**
- **명시적 패치 적용:** 같은 카드 ID의 Lua가 서로 다를 때, 파일명에 V0.9.1과 V0.9.2처럼 버전이 있고 상위 버전이 '긴급패치/핫픽스'임이 명확하면 최신 스크립트를 우선 검사합니다. 파일 추가 순서에 의존하지 않습니다.
- **충돌과 패치 구분:** 명시적 상위 패치가 있으면 `LUA_PATCH_OVERLAY` 정보만 표시하고, **상위 패치로 확인되지 않으면** 기존 `LUA_VERSION_CONFLICT` 경고를 보존합니다.
- **실측 근거:** 실제 천망성역 V0.9.1 ZIP의 본체는 원문 19종, CDB 20개 레코드(토큰 포함), 카드 Lua 19개, 공용 `cheon_common.lua` 1개입니다. V0.9.2에서 2개 Lua가 교체됩니다.
- **주의:** 브라우저 파일 보관함에는 원래 ZIP을 그대로 유지합니다. 이 변경은 검수 대상 선택만 바꿀 뿐 원본 파일이나 EDOPro 설치 파일을 수정하지 않습니다.

검수 ZIP을 차례로 등록한 뒤 **교차 검수 → 천망성역 → 구현 구조 검토 후보 / 효과 구조 대조**에서 결과를 확인하세요. V0.9.2 파일이 실제 로컬 EDOPro 설치까지 완료됐는지는 별도로 확인해야 합니다.

## V0.7 — 효과 구현 구조 대조

정적 검수에서 카드 원문 및 CDB의 번호 효과(①②③)를 추출하고, 카드별 Lua의 직접 효과 등록 호출(`c:RegisterEffect(...)`)과 소환 보조 함수의 **코드 근거**를 비교합니다.

- **원문 ①②③과 CDB 번호 효과**: 펜듈럼 효과·몬스터 효과를 구별해 나열합니다.
- **Lua 등록 근거**: `RegisterEffect` 호출 변수·파일명·줄번호·인접한 설정 함수 이름을 표시합니다.
- **주석/문자열 오탐 억제**: 주석이나 Lua 문자열 속 가짜 등록 코드는 등록으로 세지 않습니다.
- **검토 수준**: Lua가 미등록이면 대기. 직접 등록이 없거나 번호 효과 개수와 등록 수가 다르면 **구조 검토 후보**로 표시합니다. 헬퍼 함수가 있으면 직접 등록이 0건이어도 누락으로 단정하지 않습니다.
- **본문 가독성**: 기존 25:75 검수 패널과 전체 화면 검수 집중 읽기에 효과별 문구·Lua 근거를 배치합니다.
- **선별·보고**: `구현 구조 검토 후보` 필터와 `효과 구조 대조 ↓` 버튼으로 선택 테마의 구조 보고서 `종언성서_천망성역_효과구현구조_대조_V0.7.md`를 내려받습니다.
- **검수안 연동**: 구조 검토 후보를 카드별 수정안에 포함하되, 승인 없는 Lua/CDB 수정은 실행하지 않습니다.

**중요 제한:** 원문의 ①이 Lua의 e1이고 ②가 e2라고 단정할 수 없습니다. 직접 등록 수가 번호 효과 수와 같아도 효과 내용이 같은 것은 아니며, 등록 수가 적어도 공용 헬퍼나 복합 효과가 정상 구현했을 수 있습니다. 이 버전은 Lua AST 분석이나 EDOPro 실행 결과가 아니라 정적 코드 근거 비교입니다.

### 사용
1. 파일 보관함에 설계 원문, 해당 테마 CDB, 카드 Lua를 등록합니다.
2. **교차 검수 → 천망성역 → 카드 선택 → 효과 구현 구조 대조**를 펼칩니다.
3. 원문 효과와 Lua 등록 위치를 비교하고, 필요한 경우 **구현 구조 검토 후보** 필터로 좁힙니다.
4. **효과 구조 대조 ↓**로 보고서를 저장한 다음, EDOPro 실전 재현 결과와 대조합니다.

## V0.6 — 테마별 스마트 검수·실전 체크리스트

브라우저에서 원문·CDB·Lua의 **테마별 자료 연결 상태**를 확인하고, EDOPro에서 직접 재현할 테스트 목록을 생성합니다.

- **5대 테마 자동 분류:** 카드명, 확인된 카드 ID 접두부(보조 단서), ZIP·CDB/Lua 파일명 단서를 이용합니다. 일치하지 않는 파일은 억지로 분류하지 않고 미분류로 남깁니다.
- **테마별 검수 요약:** 교차 검수 상단에서 혈성·영각시계·심연묘역·천망성역·파계잔영을 선택하고 원문 종수, CDB 카드 수, 카드 Lua 수, 연결 카드 수, 정적 문제 후보 건수를 봅니다.
- **다른 테마 자료 오탐 방지:** 천망성역 CDB만 등록했을 때 혈성 등의 CDB 미등록은 오류가 아니라 **이 테마의 자료가 없음**으로 표시합니다. 해당 테마 CDB가 있는데 카드가 매칭되지 않을 때만 누락 의심을 표시합니다.
- **테마별 카드 필터:** 선택한 테마의 카드만 카드 목록과 전체 화면 검수에서 표시합니다.
- **수동 EDOPro 테스트 목록:** CDB 및 Lua가 카드 ID로 연결된 카드만 소환·발동·API·유발 타이밍 등의 테스트 시나리오로 생성하고, `종언성서_천망성역_EDOPro_수동시험목록_V0.6.md`처럼 한글 파일명으로 저장합니다.
- **모든 시험 상태 = 미실행:** 테스트 목록을 만들었다고 효과 정상 구현, 룰 적법성, 듀얼 승리/패배, 카드 성능을 검증했다고 표시하지 않습니다.
- **테마 현황 보고서:** 전체 5개 세력의 자료 범위·미분류 건수와 정적 검수 후보를 한글 Markdown으로 저장합니다.
- **입력 제한:** 기존 브라우저 보관함의 32MB/파일, 96MB/전체, 120개/등록 파일 제한 및 개별 분석기의 ZIP 용량 제한은 유지됩니다.

### 첫 실전 검수 추천

1. 기존 저장된 《종언성서》 원문 ZIP(86종)을 유지합니다.
2. **교차 검수**에서 **천망성역**을 선택합니다.
3. 천망성역의 실제 최신 CDB·Lua 패키지 ZIP을 추가합니다.
4. CDB/Lua 카드 수와 연결 여부, 정적 코드 후보의 파일·줄번호를 확인합니다.
5. **EDOPro 테스트 목록 ↓**으로 미실행 체크리스트를 저장하고 실제 EDOPro에서 검증합니다.

테마 식별과 정적 검사 결과는 프로그램 측 추정·자료 비교입니다. 실제 효과가 올바르게 실행되는지는 직접 듀얼 시험해야 하며, 이 버전은 카드 코드를 수정하지 않습니다.

- **세로 공간 절약:** 검수 요약을 작은 상태 표시줄로 바꾸고 경고 안내도 축약해 오른쪽 본문 높이를 늘렸습니다.
- **원문 바로 읽기:** CDB·Lua가 없을 때 반복 안내를 줄이고 선택한 카드 원문을 기본으로 펼칩니다.
- **모바일:** 카드 목록은 위쪽, 본문은 아래쪽으로 배치합니다. PC의 목록 접힘 설정이 모바일 목록 접근을 막지 않도록 처리합니다.
- 기존 `검수 크게 보기` 전체 화면 모드는 유지합니다.

## V0.5.1 — 카드별 수정 검토안

Lua/CDB/카드 원문 검수의 **실제 진단 코드**에서 우선순위가 붙은 수정 검토안을 자동 생성합니다. 별도 AI API·유료 서비스는 사용하지 않습니다.

- **카드별 검토안:** 정적 검사 결과의 문제 코드에 따라 관찰된 내용 → 권장 조치 → 재확인 절차를 표시합니다.

- **우선순위:** ① 즉시 확인(누락·불일치·버전 충돌) ② 수정 검토(API·이벤트·문구 차이) ③ 자료 보강(일부 패키지 미업로드 등).

- **공유:** 각 카드의 수정 검토안을 복사하거나 전체 `종언성서_카드별_수정검토안_V0.5.1.md`를 저장합니다.
- **안전:** 실제 Lua·CDB·원문 파일은 변경하지 않습니다. 수정안은 확정 패치가 아니며, 승인·백업·정적 재검사·실전 EDOPro 재현이 별도로 필요합니다.
- **확인:** 원문 86종만 불러오고 해당 테마의 CDB를 빠뜨리면 대부분은 자료 부족으로 분류해야 합니다. 자료 미등록은 카드 결함 확정이 아닙니다.

### 사용
1. 기존처럼 원문 및 CDB/Lua 파일을 브라우저 보관함에 등록합니다.
2. **교차 검수**에서 `수정 검토 우선 카드` 필터를 선택합니다.
3. 카드를 고른 뒤 `수정 검토안`을 펼쳐 근거·조치·확인 방법을 읽습니다.
4. 보고서를 내려받아 승인할 변경사항을 별도 정리합니다.

## V0.5 — Lua 심층 정적 검수

추가 구독·AI API 없이 작동하는 **규칙 기반 검사기**입니다. 기존 V0.4 파일 보관함의 Lua 파일을 재사용합니다.

- **자료가 불완전할 때:** CDB 없이 Lua만 올려도 카드별 일부 검사 가능. 원문/CDB 일치성은 별도 미검증 표시
- **보고서:** `종언성서_원문_CDB_Lua_심층검수_V0.5.md` 저장

**판정 구분:** '정적 코드 패턴 확인'은 코드가 존재한다는 뜻이며 엔진 고장을 확정하지 않습니다. '엔진 동작 검토 필요'는 의심 사항입니다. 완전한 Lua 구문검사, EDOPro 실행·효과 재현·밸런스 평가 기능은 아직 없습니다.

### 빠른 검수 순서
1. 상단 **저장 자료**에서 원문 ZIP과 테마별 CDB·Lua 시험패키지를 차례로 추가
2. **교차 검수**에서 오류 후보·검토 필요 카드 선택
3. Lua 파일·줄번호와 코드 근거 확인
4. 보고서를 내려받아 실제 EDOPro 실전 결과와 대조

## V0.4 — 스마트 파일 관리

- **한 개씩 추가:** 자료실의 원문 ZIP, 교차 검수의 패키지 ZIP/CDB/Lua, 상단의 \`＋ 추가\` 버튼 중 어느 곳에서 가져와도 동일한 파일 보관함에 누적합니다.
- **새로고침 후 자동 복원:** IndexedDB를 사용할 수 있으면 브라우저 내부에 원본 파일 바이트를 저장하여 다음 방문에 자료실과 교차 검수를 자동으로 복원합니다. 사용자 파일은 서버나 GitHub로 전송하지 않습니다.
- **파일 보관함:** 상단의 \`저장 자료 n개\`를 눌러 등록 파일명·용량·해시를 확인하고 개별 삭제·전체 삭제할 수 있습니다.
- **중복/버전 충돌:** SHA-256이 같은 파일은 추가하지 않으며, 같은 이름의 다른 내용은 모두 남긴 채 충돌 안내를 표시합니다. 구버전/최신 버전 판단은 사용자 몫입니다.
- **제한:** 파일당 32MB, 총 96MB, 최대 120개. 원문 자료실·검수 엔진에는 각각 별도 ZIP/텍스트 분석 크기 제한이 존재합니다.
- **임시 모드:** IndexedDB를 사용할 수 없는 브라우저에서는 임시 세션으로 작동하고, 지속 저장이 되지 않는다는 경고를 표시합니다.
- **YDK:** 현재 보관만 지원합니다. 덱 초동·전개 분석 기능은 이후 버전에서 개발합니다.
- **중요:** 브라우저 데이터 삭제·시크릿 모드·저장 공간 정리 정책으로 자료가 사라질 수 있습니다. **원본 ZIP과 Lua/CDB를 PC에도 반드시 보관**하세요.
- V0.3.1에서 읽던 파일은 메모리에만 있으므로, V0.4 최초 이용 시 **원문 ZIP을 한 번 더 등록**해야 합니다.

### 사용 흐름
1. 페이지에서 종언성서 원문 ZIP을 **한 번 등록**합니다.
2. \`교차 검수\`로 이동해 파계잔영 CDB/Lua 패키지 ZIP을 **별도로 등록**합니다. 두 파일을 동시에 선택할 필요가 없습니다.
3. 자료실에서 86종을 열람하고, 교차 검수에서 최신 로컬 보관 파일 집합을 비교합니다.
4. 새로고침해도 등록 목록이 다시 표시되는지 확인합니다.

## V0.3.1 — 카드 원문 집중 읽기

- 자료실에서 카드를 선택하고 **「⤢ 이 카드 원문 크게 보기」**를 누르면 화면 전체를 읽기 공간으로 사용할 수 있습니다.
- 처음에는 **18px 글씨**로 원문 효과를 모두 펼쳐서 표시합니다. **가− / 가＋**로 글씨 크기를 조정할 수 있습니다.
- 왼쪽에서 카드 검색·선택, 상단에서 이전·다음 카드 이동, **ESC**로 닫기를 지원합니다.
- 원문 카드가 로딩된 뒤에는 필요 없는 업로드 안내·통계 영역을 숨겨 기본 카드 패널도 더 넓게 사용합니다.
- 집중 읽기는 카드 효과를 보기 좋게 재배치할 뿐 원본 TXT를 수정하지 않으며, 분석·검증 결과로 간주하지 않습니다.

- 카드 효과는 ①·②·③을 따로 접거나 펼치며, \`모두 펼치기\` 기능을 제공합니다.
- 원문 메모는 자료실 하단의 접이식 서랍에서 확인합니다.

## V0.2 — 원문·CDB·Lua 교차 검수
- **파일 하나씩 누적 가능(V0.4)**: 원문 TXT/ZIP부터 등록한 후 각 테마의 시험패키지 ZIP 또는 개별 CDB/Lua를 따로 추가할 수 있습니다.

- Lua: 카드 ID의 \`c<ID>.lua\` 대응, \`initial_effect\` 존재, 공용 \`*_common.lua\` 참조 검사
- 효과 문구: 원문과 CDB의 번호 붙은 효과 항목을 대조하고 차이와 순서 확인
- 파일 버전 충돌, 카드 ID/이름 누락, 선택지 설명 문자열 누락 가능성 경고
- 실제 EDOPro 구동 없이 **정적 진단 보고서** Markdown 파일로 저장
- CDB만 업로드한 경우에도 **CDB↔Lua 검사는 가능**, 설계 원문 대조는 미검증으로 표시

### 실제 사용
1. 상단의 **교차 검수** 탭을 엽니다.
2. **원문 ZIP**을 먼저 등록하고, 그다음 **파계잔영 시험패키지 ZIP**을 따로 등록해도 됩니다.
3. 오류 후보/검토 필요 탭을 선택해 카드별 근거를 확인합니다.
4. \`종언성서_원문_CDB_Lua_정적검수_V0.2.md\` 보고서를 내려받습니다.

> **검사 수준 경계**: 문구 비교는 유사한 뜻의 다른 표현도 차이로 표시할 수 있습니다. Lua 검사는 파일과 일부 정적 패턴만 확인하므로, Lua 구문 전체·EDOPro API·효과의 적법한 처리·실전 성능까지 판정하지 않습니다. '오류 후보'가 반드시 실제 버그를 뜻하지는 않습니다.

## 파일과 개인정보
- 업로드한 파일을 서버로 보내지 않습니다. 브라우저 내에서만 분석하며, 사용자가 등록한 파일은 가능한 경우 IndexedDB에 로컬 저장됩니다. 저장이 불가능하면 임시 모드로 동작합니다.
- 첫 실행 시 JSZip과 sql.js 코드·WASM은 공개 CDN을 통해 로드됩니다. **실제 카드 ZIP·CDB·Lua 데이터는 CDN으로 업로드하지 않습니다.**
- GitHub 저장소에는 업로드한 원본 CDB·Lua·개인 파일을 자동 커밋하지 않습니다. 등록 자료는 사이트별 브라우저 IndexedDB에 저장되며, 다른 기기·브라우저에는 자동 동기화되지 않습니다.
- 공개 페이지를 사용하더라도 업로드 내용이 공개 저장소에 게시되지는 않습니다.
